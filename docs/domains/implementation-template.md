# 领域实现文档模板

> 本模板用于记录已经实现或正在本任务中确认的事实。不得使用空泛占位语句；尚未实现的内容应明确标记为非目标、已知限制或后续任务。

## 1. 业务定位

- 用户场景和业务目标。
- 本功能提供的用户能力和业务结果。
- 范围、非目标和与相邻功能的区别。

## 2. 所有权与代码地图

- 负责人和领域目录。
- router、schema、service、repository、model、integration、前端页面和测试的实际路径。
- 本领域拥有的数据和只读依赖。
- 禁止依赖和跨模块写入。

## 3. 实现架构

- 使用 Mermaid 描述组件关系或运行时序。
- 说明入口、应用服务、领域逻辑、持久化和外部适配器的职责。
- 说明请求、数据、状态和错误如何在组件之间流动。
- 记录同步/异步边界、事务边界和依赖注入位置。

## 4. 数据、状态与接口

- 核心实体、字段和派生字段。
- 状态机、合法流转、权限和软删除规则。
- 公开 API 或内部接口链接；不复制全量 API 契约。
- 稳定错误码、幂等规则和前端兜底。

## 5. 核心算法（后端必填）

### 5.1 输入、输出与不变量

- 输入数据及其校验条件。
- 输出结构和调用方依赖。
- 权限、范围、顺序、覆盖率和一致性不变量。

### 5.2 算法步骤

- 用编号步骤、伪代码或流程图描述真实实现。
- 说明排序、过滤、去重、聚合、批处理、状态汇总或渲染规则。
- 说明事务提交、回滚、补偿和重试顺序。

### 5.3 复杂度与资源预算

- 时间和空间复杂度，或主要数据库查询数量。
- 模型 token budget、batch size、Top-K、文件大小、题量或日期范围上限。
- 当前 POC 限制和规模增长后的优化触发条件。

### 5.4 AI 生成附加要求

- Prompt 的职责边界和禁止补充的外部事实。
- Pydantic 结构化输出 schema。
- Map/reduce、全材料覆盖、去重和最终筛选算法。
- 引用允许集合、引用 ID 回填和伪引用防护。
- 模型、schema、覆盖和持久化失败的处理。

前端领域文档不需要填写后端算法，但必须写清组件状态、交互数据流、API 适配和异常降级。

## 6. 测试与验收

- 单元、API、contract、integration 和端到端测试路径。
- 关键主流程、异常、权限和回归场景。
- 精确运行命令和最近验证结果。
- 手工验收或真实模型/PDF 日志入口。

## 7. 决策、限制与演进

- 已确认的实现决策和原因。
- 与 PRD、全局架构和 API 文档的链接。
- 已知限制、技术债和后续演进条件。
- 最后更新日期及对应提交。

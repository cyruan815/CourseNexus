# Implementation Roadmap

## 阶段 0：项目基座

目标：

- 建立前后端项目骨架。
- 建立 docs 知识库和工程约定。
- 建立数据库 baseline migration。

验收：

- `pnpm test` 可运行并通过。
- 文档能说明项目目标、模块边界、数据契约和开发入口。

状态：已完成基线，后续随实现持续维护。

## 当前基础设施主线边界

当前基础设施阶段以稳定后端链路为核心，前端只作为最小集成验证工作台。

当前主线保留：

- 前端 API client、token 管理和路由壳。
- 极简课程列表和课程详情空工作台，用于验证课程选择和页面挂载区域。
- 后端接口、service、repository、测试和文档契约。
- 后端链路：注册 / 登录 -> 创建课程 -> 上传资料 -> 解析 -> 写入 `MaterialChunk` -> `resolve_context()` -> `ask_question()` -> 保存回答和引用。

当前主线暂缓：

- 资料上传面板、资料范围选择器和资料状态列表等完整前端资料交互。
- 课程问答面板、引用列表和追问交互等完整前端问答体验。

上述前端交互能力不作为当前基础设施验收条件，应在 Materials / Context / QA 后端接口稳定后作为后续独立前端任务分发。

## 阶段 1：Walking Skeleton

目标：

- 建立统一错误响应、请求 ID、配置读取和数据库依赖。
- 实现本地账号最小闭环。
- 实现课程创建、列表、详情的最小 API。
- 建立前端 API client、登录态、路由壳、课程列表和课程详情空工作台。

验收：

- 用户可以在本地创建或使用测试账号。
- 前端可以通过 API 获取课程列表并进入课程详情。
- 课程数据具备 `user_id` 归属边界。

## 阶段 2：课程资料管理

目标：

- 实现资料文件夹、资料上传记录、资料列表和解析状态。
- 建立本地文件存储目录和上传校验。
- 先落地解析任务状态，不急于覆盖所有文件类型。

验收：

- 用户可以通过后端 API 在课程下添加资料。
- 资料状态可以表达 `pending`、`parsing`、`parsed`、`parse_failed`。
- 失败资料不能进入问答或生成上下文。

## 阶段 3：资料上下文层

目标：

- 实现资料文本抽取的最小适配层。
- 实现 `material_chunks` 写入、查询和引用定位。
- 建立课程范围、资料范围和任务上下文的统一筛选接口。
- 使用 Docling 解析复杂文档并保留标题、页码和表格等结构。
- 使用 LlamaIndex + OpenAI Embeddings 将 chunk 写入本地 Chroma `PersistentClient`。
- 分离 `retrieve_relevant_context()` 和 `iter_material_context_batches()` 两类上下文接口。

验收：

- 已解析资料可以生成可检索 chunk。
- chunk 可以追溯到资料、页码或位置。
- 问答检索通过 `user_id`、`course_id`、`material_scope` metadata 硬过滤，不能跨范围命中。
- 指定材料生成能证明每份选中资料都进入至少一个处理批次。
- 上下文层不直接调用模型，不保存生成内容。

## 阶段 4：课程问答

目标：

- 实现 conversation、message 和 source citation 的最小 API。
- 接入模型 adapter 占位或真实 provider。
- 回答必须带可追溯引用。
- 问答基于 Chroma Top-K 语义检索，不再顺序截取前若干 chunk。

验收：

- 用户可以通过后端 API 围绕单门课程提问。
- 回答保存到消息表。
- 引用来源能回到 `CourseMaterial` / `MaterialChunk`。

## 阶段 5：独立生成内容

目标：

- 实现 Quiz、Flashcard、Mindmap、Outline、Knowledge List 等生成入口。
- 统一保存到 `ai_generated_contents`。
- 引用统一保存到 `source_citations`。

验收：

- 每类生成结果有结构化 `content_json`。
- 所有选中资料按顺序分批处理并经 map-reduce 汇总，不能用一次 Top-K 检索代替全材料覆盖。
- 生成失败保存失败状态并允许重试。
- 各生成模块互不直接调用。

## 阶段 6：学习计划与执行

目标：

- 实现单课程学习计划生成。
- 写入 `study_plans`、`study_tasks`、`study_subtasks`。
- 实现计划执行页、二级任务完成和打卡记录。

验收：

- 一个学习计划只绑定一门课程。
- 首页今日待办和大日历只读聚合任务。
- 完成二级任务后同步打卡状态。

## 阶段 7：导出与质量闭环

目标：

- 实现今日讲义、任务测试题和 PDF 导出。
- 建立生成质量、引用质量和失败重试的验收清单。
- 补齐关键流程的端到端测试或手动验收记录。

验收：

- 导出内容可追溯到资料和生成结果。
- 失败有错误码、日志和重试入口。
- 核心学习闭环可完整演示。

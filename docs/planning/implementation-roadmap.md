## 2. V1 发布动作

M07 合并后，单机 V1 的建设项即完成。后续发布动作不自动扩大产品范围：

1. 确认 M07 CI 全绿并合并到 `dev`。
2. 在实际发布提交上复跑 `pnpm test`、`pnpm frontend:build`、空库/旧库迁移和真实模型脚本。
3. 核对 `tmp/` 中的临时数据库、日志、截图和报告，负责人确认后再清理。
4. 如需发布稳定版本，另行授权并创建 `dev -> main` PR；不直接推送 `main`。
5. 如目标机器存在真实旧数据，按本地存储迁移文档先停进程、备份并在副本演练，不自动移动或删除旧位置。

## 3. 后续优先级

### 3.1 共享或公网部署前必须处理

- S02 服务端会话 + HttpOnly Cookie、退出单会话撤销和 CSRF/CORS 策略。
- S04 请求、解压、模型并发、用户额度和重试总预算。
- S05 Chromium PDF 渲染网络隔离。
- M06 Provider/任务指标、积压、失败率与成本可观测性。
- 部署配置、TLS、备份恢复演练、对象存储或受控共享文件存储。

### 3.2 数据规模或长耗时成为瓶颈时

- R01 SQLite 持久化 Job 与独立单机 Worker，处理排队、租约、取消、恢复和迟到结果。
- R03 完整任务化的一致性状态机，继续收口问答、生成和导出的失败/恢复语义。
- M05 稳定 cursor 分页。
- PostgreSQL、对象存储和多进程写入协调只在证据证明需要时评估，不作为默认升级。

### 3.3 体验与维护演进

- P10 作答历史、服务端判分、错题本、笔记和掌握度反馈。
- M01 大型模块拆分与 Handout 公共校验入口。
- M02 服务端状态逐步迁移到 Query，保留本地草稿/编辑状态在页面状态层。
- M03 路由与 Office/图表等重依赖懒加载预算。
- 图片 OCR、复杂 PDF/Office 版式、混合检索、去重与 rerank 继续按真实失败样本演进。

## 4. 路线原则

- 先以失败证据、数据规模或部署边界证明需求，再引入队列、缓存、微服务或数据库迁移。
- 每个后续事项继续使用独立分支和 PR；数据模型、公共 API 或核心依赖变更需单独评审。
- 延期项始终保留当前限制和触发条件，不能因 V1 完成而被标记为已实现。
- 正式状态以本目录、产品/API/架构文档和合并 PR 为准，不再引用 `tmp/v1-closeout-plan-review.md` 作为权威来源。

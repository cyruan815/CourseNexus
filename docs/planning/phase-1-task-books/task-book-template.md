# 任务书写作模板

每份任务书必须使用以下结构。不得使用 `TBD`、`TODO`、“适当处理”、“补充测试”等无法验收的表述。

## 1. 任务信息

- 编号与名称。
- 负责人角色。
- 目标：一句话说明完成后用户或上游模块获得什么能力。
- 前置依赖：精确到任务编号、接口、schema 或已合并提交。
- 范围外事项：明确本任务不实现什么。

## 2. 实现范围

- 按可独立测试的小步骤列出实现内容。
- 写明创建、修改、禁止修改的精确文件或目录。
- 写明输入、输出、错误码、状态流转、权限和幂等规则。
- 对前端写清页面状态、交互、路由、组件和 API 调用。
- 对后端写清 router、schema、service、repository、模型、迁移和依赖注入边界。

## 3. 字段与接口

- 列出请求和响应示例。
- 列出新增或复用的 Pydantic/TypeScript 类型。
- 引用 `shared-contract.md` 中不可改变的字段。
- 标注哪些接口已存在、哪些由本任务新增、哪些仅做占位。

## 4. 测试计划

- 先写失败测试，再做最小实现。
- 列出精确测试文件、测试场景、运行命令和预期结果。
- 同时覆盖主流程、空状态、错误状态、权限边界、重复提交和相邻模块回归。
- 自动化测试不得依赖 live network。

## 5. 验收标准

- 使用复选框列出可观察结果，不能只写“功能正常”。
- 每条包含输入条件、用户操作或 API 调用、预期数据和预期 UI/状态。
- 区分自动化验收与人工验收。

## 6. 交付物

- 代码文件与测试文件。
- API 或字段文档。
- 迁移文件（仅 S01 允许）。
- 中文测试日志或验收记录。
- 独立 Conventional Commit 列表。

## 7. 文档同步

- 按共享协作契约的文档同步矩阵列出具体文件。
- 如果不需要更新某类文档，写明原因。
- 不得直接修改与任务无关的 PRD 内容。

## 8. 冲突与注意事项

- 列出可能触碰的共享热点和唯一负责人。
- 列出必须严格复用的公共接口。
- 列出明确禁止的依赖、表、字段和跨模块写操作。
- 说明与另外两名开发者的集成顺序。

## 9. 完成检查表

- [ ] 实现范围全部完成。
- [ ] 目标自动化测试通过。
- [ ] 受影响模块回归通过。
- [ ] 文档同步完成。
- [ ] `git diff --check` 通过。
- [ ] 修改文件未越过所有权边界。
- [ ] 每个小功能已独立提交。

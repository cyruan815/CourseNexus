# Tech Debt Tracker

## 维护口径

本文件记录当前仍会影响后续演进的技术债，并保留已经关闭事项的证据。V1 产品、可靠性和安全事项的正式状态以 [v1-completion-matrix.md](v1-completion-matrix.md) 为准；临时评审稿不作为状态来源。

状态含义：

- `已关闭`：当前约定范围已经实现并有代码或验收证据。
- `部分完成`：其中一段已落地，剩余范围必须继续明确列出。
- `已接受延期`：单机 V1 接受当前限制，但触发更高部署或规模条件前必须处理。
- `待处理`：尚未排期，也没有作为 V1 明确接受的范围决定。

## 关键延期边界

### S05 / TD-016：PDF 渲染网络隔离

当前只接受可信本机、小规模使用。只要后端部署到能访问内网/云元数据的机器、开放给不完全可信用户，或 PDF 导出改成自动批量任务，就必须先实施请求拦截。默认方案是 Chromium 只允许本地文档和明确审核的静态资源；如确需远程图片，必须由受控下载器验证协议、域名、DNS/重定向、大小、超时和 MIME，不能让浏览器直接访问任意 URL。

完成标准至少覆盖环回、私网、云元数据和重定向拒绝，以及纯文本、表格和本地可信资源正常导出。

### R03 / TD-017：资料理解质量

R02 解决“重解析失败破坏旧可用版本”，但不代表解析质量问题全部关闭。后续应依据真实失败样本处理：页数/元素完整性、OCR 降级、重复目录、结构化切块、混合检索、rerank 和不同题型的召回预算。升级必须继续保留版本化写入、当前生效指针、历史引用版本和只读对账契约。

### M01 / TD-020：模块解耦

Handout 模块应提供稳定的 `validate_handout_markdown()` 一类公共入口，统一 Mermaid 禁止、安全 SVG 和必需图示规则。单批次 generator 与多批次 reducer 调用同一入口；重构不得顺便改变生成错误码、数据库或公开 API。

## 更新规则

- 新增、关闭或拆分技术债时更新表格，并注明代码、PR、测试或验收证据。
- 关闭事项保留记录，不通过删除条目制造“无技术债”假象。
- 技术债影响产品范围、模块边界、API 或数据契约时，同步更新对应正式文档。
- 从单机 V1 扩展到共享或公网部署前，必须重新审查所有标记“共享部署前”的条目。

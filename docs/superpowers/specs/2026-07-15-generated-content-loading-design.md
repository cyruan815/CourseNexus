# AI 生成内容列表即时反馈设计

## 目标

用户点击五个生成式功能后，不再面对没有反馈的等待过程。列表应立即出现对应的临时加载项，并在请求结束后原位切换成真实生成记录。

涉及五个功能：

- Quiz
- 知识闪卡
- 思维导图
- 复习提纲
- 知识点清单

本设计只改变课程详情页中“AI 生成内容”列表的反馈与时间文案，不改变各生成器接口、生成结果详情页或生成算法。

## 最终视觉

采用方案 C 的强调型加载项，但降低扫光速度：

- 加载项保留现有列表项目的尺寸、圆角和排版。
- 使用淡蓝紫渐变边框和浅色背景。
- 右侧显示转圈动画及“生成中”。
- 背景光带从左向右扫描，一个完整周期约 2.1 秒。
- 光带经过后有短暂停顿，避免动画显得急促。
- 加载项使用禁用光标且不能跳转详情页。
- 多个并发任务分别显示各自的加载动画。
- 正常项目不显示“已完成”图标、徽章或状态胶囊。

## 标题规则

列表标题只显示功能名称，不附加括号、数量或后端生成标题：

| 内容类型 | 列表标题 |
| --- | --- |
| `quiz` | Quiz |
| `flashcard` | 知识闪卡 |
| `mindmap` | 思维导图 |
| `outline` | 复习提纲 |
| `knowledge_list` | 知识点清单 |

例如列表中显示“知识闪卡”，不显示“知识闪卡（20 张）”。生成结果详情页标题不在本次修改范围内。

## 加载文案

不同功能可以显示对应的过程提示：

| 内容类型 | 加载说明 |
| --- | --- |
| `quiz` | 正在生成题目与逐项解析 |
| `flashcard` | 正在整理记忆卡片 |
| `mindmap` | 正在梳理概念关系 |
| `outline` | 正在整理复习结构 |
| `knowledge_list` | 正在提取关键概念 |

右侧统一显示转圈动画和“生成中”。

## 相对时间规则

正常项目下方的小字只显示生成时间距离现在多久，不再显示内容类型和生成状态：

- 不足 1 分钟：`刚刚`
- 1 至 59 分钟：向下取整为 `N 分钟前`
- 1 至 23 小时：向下取整为 `N 小时前`
- 达到 1 天：向下取整为 `N 天前`

超过一天后继续按天显示，不切换成月份或具体日期。时间依据 `created_at` 计算；组件运行期间按固定周期刷新，使跨越分钟或小时边界后能自动更新。

## 状态与数据流

1. 用户点击任意生成工具。
2. 前端立即创建一个仅存在于页面状态中的临时加载项，放到列表顶部。
3. 临时项使用独立的本地 ID，因此允许多个功能或同一功能并发生成。
4. 前端照常调用现有生成接口，不修改请求参数和后端协议。
5. 接口成功返回后，用真实生成记录替换对应的临时项，保持其列表位置稳定。
6. 真实记录恢复可点击状态，并跳转到原有详情页。
7. 接口抛出网络错误时，移除对应临时项并沿用页面现有错误提示。
8. 后端返回 `generation_status=failed` 的记录时，用该真实失败记录替换临时项，沿用系统现有失败记录处理方式。

## 前端组件边界

建议把职责拆成三个小单元：

- 相对时间格式化函数：输入 `created_at` 和当前时间，输出中文相对时间。
- 生成列表项组件：根据“临时加载项”或“真实记录”渲染加载态、普通态或失败态。
- 并发任务状态：保存临时 ID、内容类型和请求对应关系，负责精确替换或删除某一个任务。

这样不会把动画、时间计算和网络请求全部堆积在课程详情页组件中，也便于分别测试。

## 可访问性与动画降级

- 加载项使用 `aria-disabled=true`，不渲染成可导航链接。
- 转圈图标不单独朗读，加载项提供可读的“正在生成”状态文本。
- 对启用 `prefers-reduced-motion: reduce` 的用户关闭扫光和旋转动画，但保留静态加载颜色及“生成中”文本。
- 动画仅改变 `transform`，避免触发频繁布局计算。

## 验收标准

- 点击五种工具中的任意一种后，列表顶部立即出现对应加载项。
- 加载项不可点击，带慢速转圈及从左向右扫光。
- 可以同时存在多个加载项，任务之间互不覆盖。
- 一个任务完成或失败时，只更新自己的列表项。
- 成功项目可正常进入原详情页，且右侧没有“已完成”标记。
- 标题不包含括号和数量。
- 小字按分钟、小时、天正确显示相对时间。
- 刷新已有列表、空列表、请求异常和减少动画偏好均有测试覆盖。

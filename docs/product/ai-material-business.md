# AI 资料业务线

## 1. 业务定位

CourseNexus 的 AI 能力围绕“用户明确选择的课程资料”展开。系统不在当前阶段建设会自动判断意图、跨课程寻找资料的通用 Agent，也不把 AI 能力独立成另一套业务平台。

用户、课程、资料范围、权限、生成记录和学习任务仍由 CourseNexus 管理；AI 能力负责把选定资料转为可检索上下文，并基于这些上下文完成问答或结构化学习内容生成。

所有 AI 请求必须包含：

- 当前用户和单门课程；
- 明确的 `material_scope`，可表示当前课程全部已解析资料或指定资料 / 目录；
- 问答文本，或具体生成类型及参数；
- 可回溯到 `CourseMaterial` / `MaterialChunk` 的引用来源。

## 2. 两类业务

### 2.1 选定材料范围内的 RAG 问答

用户先选择一个、多个或当前课程全部已解析资料，再提出问题。系统只在这个范围内进行语义检索，把最相关的片段交给模型回答，并展示真实引用。

```text
选择材料范围
-> 提出问题
-> 在范围内语义检索 Top-K 片段
-> 基于命中片段生成回答
-> 保存对话、回答和引用
```

产品规则：

- 问答的目标是相关性，不要求把所有选中资料都送入单次模型调用。
- 材料范围是硬过滤条件，不能因语义相似而检索到范围外资料。
- 没有可用资料或没有可靠命中时返回无来源状态，不生成伪引用。
- 追问沿用会话，但每次请求仍以当次 `material_scope` 为准。

### 2.2 指定材料生成

用户先选择要参与生成的资料，再选择一种学习能力。该类业务的目标是材料覆盖，不是寻找少量最相关片段。

包含：

- 学习计划和计划学习模式中的资料分析；
- Flashcard；
- Quiz / 课程自测；
- Mindmap；
- 复习提纲；
- 知识点清单；
- 今日讲义；
- 任务测试题；
- 后续同类的总结、重点提取和结构化学习内容。

```text
选择材料范围
-> 按材料和原始顺序读取全部可用切片
-> 按上下文预算分批提取中间结果
-> 汇总、去重并生成目标结构
-> 保存业务结果和引用
```

产品规则：

- 每份选中且已解析的资料都必须参与生成，不能用一次普通 Top-K 检索代替全材料处理。
- 材料过长时采用分批提取和汇总，不能静默截断后宣称已使用全部材料。
- Flashcard、Quiz、Mindmap、提纲、知识点清单、讲义和任务测试题统一保存到 `AIGeneratedContent`；学习计划保存到 `StudyPlan` / `StudyTask` / `StudySubTask`。
- 不同生成能力拥有各自的结构化输出和质量规则，但共享资料范围、上下文和引用能力。
- 学习计划保存时只生成任务结构；今日讲义和任务测试题在执行阶段按需生成。

## 3. 共同业务约束

- 只有 `parse_status = parsed` 且未删除的资料可进入上下文。
- CourseNexus 后端负责用户和课程归属校验，AI 库不承担权限判断。
- 引用必须能回到资料名称、页码 / 页序号和命中文本；可定位时同时保存 `chunk_id`。
- 模型输出必须经过项目内部 Pydantic schema 校验后才能写入业务表。
- 解析、检索或模型调用失败必须返回稳定错误码，并保留重试入口。
- 当前 POC 使用单机本地资料处理与向量持久化，不使用 Docker；OpenAI API 是唯一外部 AI 服务。

## 4. 当前范围和非目标

当前范围是单用户请求下、单课程、显式材料范围的资料问答与生成。以下能力暂不纳入：

- 跨课程全局检索；
- Agent 自动选择课程或文件；
- 多用户共享知识库；
- 自动联网补充资料；
- 自建模型推理服务；
- RAGFlow 平台接入。

RAGFlow 仅作为资料量、协作部署或检索质量需求明显增长后的 future 备选，不参与当前实现。

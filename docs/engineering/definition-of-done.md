# Definition of Done v0.1

## 代码完成标准

- 实现满足 PRD 对应流程和边界，不只满足页面展示。
- 后端完成登录态校验和 `user_id` 数据归属校验。
- 关键状态流转可验证，包括资料解析、生成状态、计划任务和二级任务完成。
- 失败路径有稳定错误码、用户可理解提示和可重试策略。
- 前端覆盖 loading、empty、error、disabled 或 generating 等必要状态。
- 重复点击或重复请求不会造成重复生成、重复完成或重复累计。
- 所有新增或修改的后端接口都能通过请求日志定位状态码、耗时和 `request_id`。
- 状态变更、外部系统调用、长耗时任务以及被转换为失败状态的异常已记录关键业务结果。
- 错误日志包含稳定错误码或原始异常，不只记录“操作失败”等无原因结论。

## 基础测试或手动验收标准

- 后端新增核心逻辑有 pytest 或明确手动验收说明。
- 前端新增关键交互有 Vitest 或明确手动验收说明。
- 至少验证成功路径、失败路径、未登录、无权限和空状态。
- Agent / 生成类能力至少验证有资料命中、无资料命中、生成失败和重试。
- 新增日志已通过测试或手动验收确认关键字段完整，且不包含密码、Token、资料正文等敏感信息。

## 文档完成标准

- 产品行为变化已更新 `docs/product/` 或 PRD 入口。
- 架构、模块边界、核心依赖变化已更新 `docs/architecture/`。
- API、字段、状态、错误码、数据契约变化已更新 `docs/api-data/`。
- 工程约定、测试方式、协作方式变化已更新 `docs/engineering/`。
- 具体模块文档只有在模块边界稳定并进入开发后才创建。

## API / 数据契约完成标准

- 请求字段、响应字段、错误码和状态枚举明确。
- 权限和数据归属规则明确。
- 空列表、分页、时间格式、ID 格式和幂等规则明确。
- 引用来源最小字段明确：资料 ID、资料名快照、页码或页序号、命中文本片段。
- 破坏性变更已说明兼容或迁移方式。

## Review 完成标准

- Review 已检查 PRD 口径、模块边界、数据归属、状态流转和错误处理。
- Review 已检查关键成功、失败、耗时日志及其脱敏范围。
- 必要测试或手动验收已经执行并记录结果。
- 文档更新已经和代码 / 契约保持一致。
- 没有无关重构、临时文件或未说明的依赖变化。

## 不满足 DoD 的处理

不满足以上标准时，不应合并或交付。可以拆小范围交付，但必须明确剩余缺口、风险和补齐位置。
